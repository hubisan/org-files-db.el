#+TITLE: Repository-specific AI Instructions
#+STARTUP: showall

* Checks

- Run ~make fmt~ after editing Emacs Lisp.
- Run ~make ci~ before marking a task ~DONE~.
- Use ~make compile~, ~make lint~, and ~make test~ to investigate failures.
- Add or update Buttercup tests for behavior changes.
- Treat compiler and linter warnings as errors.

* Modules

- Put package files in ~lisp/~ and tests in ~tests/~.
- Keep public ~defcustom~ and ~defface~ forms in the core file (...-core.el).
- Keep Core small and free from specialized implementation logic.
- Avoid circular module dependencies.

* Symbol names

Prefix all global symbols with the package prefix.

Name public symbols by their user-facing purpose, not by the file that implements them.

A public symbol can include a subsystem name when that subsystem is part of the user-facing concept.

Private symbols must use the prefix of their defining file or module before ~--~.

Example for package ~example~ and module ~example-process.el~:

#+begin_example
example-query
example-config
example-process-start

example-process--resolve-executable
example-process--run
#+end_example

Do not use a generic private prefix such as ~example--*~ when one module clearly owns the symbol.

Apply the same rule to private functions, variables, and constants.

Use a separate test prefix such as ~example-test--*~ for test-only helpers.

* Emacs Lisp style

- Use one space after a full stop. Never use two-space sentence spacing.
- Start docstrings, messages, and error strings with a capital letter.
- Do not add an empty line after the first line of a docstring.
- Avoid obsolete Emacs APIs.
- Use ~when-let*~ instead of obsolete ~when-let~.
- Do not leave unused lexical variables.
- When renaming private state, update all bindings and readers.
- Pass process arguments separately. Do not build shell command strings.
- Avoid unrelated formatting changes.

* Generated files

Do not edit generated Eask state, package archives, ~*.elc~, autoload files, package files, or temporary test output.
