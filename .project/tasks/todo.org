* Rebuild decisions

The current package is reference material only. The rebuild does not preserve the old internal architecture or compatibility aliases.

- Use the public ~orgfdb~ CLI as the only Rust seam.
- Use ~presentation-json~ version 2 as the internal Emacs presentation model.
- Keep ~orgfdb query --format json~ unchanged on the Rust side, but do not use it as the normal Emacs presentation model.
- Let Rust own columns, sorting, row expansion, width calculation, truncation, padding, and presentation caching.
- Keep Emacs responsible for configuration, process control, JSON decoding, faces, completion, navigation, and user actions.
- Use synchronous query and view commands. A user starts a query because they want the result immediately.
- Do not add asynchronous query completion that can appear after the user starts other work.
- The watcher is the only long-running child process that Emacs can start.
- Do not use Child Emacs, ~async.el~, presentation dumps, or an Emacs presentation cache.
- Keep Search outside this rebuild. Do not port ~org-files-db-search.el~.
- Use standard Emacs completion through ~completing-read~.
- Keep Embark optional.
- Do not require ~embark-consult~.
- A view is a named query with presentation configuration and optional behaviour.
- A view does not imply caching.
- ~:cache t~ enables the Rust materialized-view path only while ~org-files-db-cache-mode~ is active.
- Without active caching, every view can run as a one-shot ~presentation-json~ query.
- View names are unique in Emacs.
- Rust view names use a private per-Emacs-session namespace.
- Use named orgfdb configurations and one explicit default configuration.
- A view can select one configuration with ~:config~.
- A view without ~:config~ uses the default configuration.
- Default actions are configured separately for ~headings~, ~files~, and ~links~.
- A view can override its default action with ~:action~.
- Actions receive the original Rust result, not a presentation row.
- Keep ~row_context~ as internal candidate metadata for later integrations.
- Query and view commands return the selected original result to Lisp callers.
- Interactive actions give short user feedback and do not expose raw result structures.

Provide:

#+begin_src emacs-lisp

(org-files-db-cache-start)
(org-files-db-cache-stop)

#+end_src

~org-files-db-cache-start~ enables ~org-files-db-cache-mode~.

~org-files-db-cache-stop~ disables ~org-files-db-cache-mode~.

With a non-nil argument, ~org-files-db-cache-stop~ also disables watch mode.

Cache mode activation must:

1. make sure that watch mode is active
2. make sure that every cached view has a watcher for its effective configuration
3. resolve every cached view to its complete effective definition
4. create a private per-Emacs-session Rust view name
5. register every ~:cache t~ view
6. store an activation snapshot

The effective snapshot includes inherited values such as:

- default configuration
- default columns
- default sorting
- action data requirements

If any registration fails, roll back all registrations from that activation attempt.

If cache mode started watch mode during the same attempt, restore the previous watch-mode state on failure.

Cache mode deactivation must remove the registrations from its activation snapshot.

Do not recalculate the list from the current ~org-files-db-views~ value during cleanup.

If a cached view definition changes while cache mode is active, report a clear error when that view is used.

Tell the user to restart ~org-files-db-cache-mode~ to apply the new definition.

When cache mode is active and ~:cache t~ is set:

- read the Rust view with ~orgfdb view read~
- do not fall back silently to a one-shot query on rebuild or watcher errors

If ~view read~ reports ~view_not_found~ after a watcher restart:

- register the stored activation snapshot again
- retry the read once

Do not use the current changed Lisp definition for this recovery.

Do not allow ~org-files-db-watch-mode~ to stop while cache mode is active. Signal a user error instead.

Acceptance criteria:

- Views work with and without cache mode.
- ~:cache t~ is an opt-in performance choice, not a functional requirement.
- Cached views use ~view register~ and ~view read~.
- Non-cached views use the same one-shot query pipeline as ~org-files-db-query~.
- View names are unique in Emacs.
- Rust view names are private to one Emacs session.
- View configuration changes require a cache-mode restart.
- Cleanup removes exactly the registrations created by the active snapshot.
- Cache failures are visible and do not trigger a silent query fallback.
- Watcher restart recovery uses the stored snapshot.
- Normal Emacs exit removes active Emacs-owned registrations.
