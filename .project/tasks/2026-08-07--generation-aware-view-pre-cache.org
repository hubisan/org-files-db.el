Implement the active task ~Add generation-aware asynchronous pre-caching for predefined views~ in one pass and return only changed or new files as a ZIP archive.

* Planning

** Problem summary

Large predefined views currently execute ~orgfdb~, parse JSON, prepare rows, calculate widths, and format completion candidates on every invocation. The Rust CLI now exposes authoritative database identity, generation, change-journal, and file-restricted query interfaces that can support a correct in-memory prepared-view cache.

** Goals

- Add opt-in ~:pre-cache t~ support for predefined query and search views.
- Reuse prepared candidates only when ~database_id~ and ~generation~ still match.
- Patch complete structural query views from authoritative affected-file sets.
- Rebuild search and unsafe query views completely.
- Build background replacements with ~async.el~ and publish them only after final state and token validation.
- Add force-refresh, refresh, clear, limits, LRU eviction, idle prewarming, polling, optional file notification, failure recording, and package-mutation staleness.
- Keep direct query and search calls fresh and uncached.

** Non-goals

- Persistent caches across Emacs restarts.
- Direct SQLite access.
- Rust schema changes.
- Selective FTS ranking updates.
- Stale-while-refresh display.
- New row-expansion or sorting semantics that are not already implemented.

** Architecture

- Add ~org-files-db-cache.el~ for cache entries, state parsing, patching, worker lifecycle, timers, watchers, limits, and diagnostics.
- Keep public view commands in ~org-files-db-views.el~ and delegate cache work to the cache module.
- Refactor query and search orchestration into shared fetch helpers reusable by public commands and cache workers.
- Extend the shared core process layer with optional stdin for restricted structural queries and add presentation-reading helpers.
- Use an internal source-mutation hook in core so actions can mark relevant caches potentially stale without introducing module cycles.
- Return plain serializable result data from async workers and reconstruct theme-sensitive presentation state in the main Emacs process.

** Execution plan

1. Extend core process and presentation APIs.

4. Implement restricted-query patching and rebuild fallback.

6. Add LRU limits, explicit cache commands, failures, and source-mutation staleness.

8. Run all available static checks and package tests where the environment permits.

** Risks & assumptions

- The documented ~status~, ~changes~, and ~--restrict-files-json -~ contracts are treated as authoritative.
- Optional database-path fields are accepted from status output; when absent, automatic refresh uses polling rather than guessing a SQLite path.
- Current package versions do not yet implement configurable sorting or row expansion; cache keys include those view properties and patch safety rejects unsupported active forms.
- Default structural query order is reconstructed by canonical owning path and source position during patch merge; uncertain or incomplete ownership falls back to a full rebuild.

** Open questions

None. Missing optional database-path output is handled through polling as allowed by the task.

* Results

** Approach

- Added a dedicated in-memory cache module for predefined query and search views that opt in with ~:pre-cache t~.
- Used ~orgfdb status~ database identity and committed generation as the authoritative freshness signal.
- Added complete synchronous publication, warm prepared-candidate reuse, forced refresh, cache clearing, conservative limits, LRU eviction, idle prewarming, fallback polling, and optional debounced SQLite file notifications.
- Added authoritative ~orgfdb changes~ handling and file-restricted structural query patches that remove all rows owned by upserted or deleted paths, rerun only upsert paths, merge independent logical rows, recalculate widths, and reformat the complete replacement before atomic publication.
- Added one-at-a-time ~async.el~ workers for full rebuilds and restricted patches. Workers return serializable logical rows; the main process reapplies theme-sensitive faces and validates database identity, generation, cache key, view token, and refresh token immediately before publication.
- Kept direct ~org-files-db-query~ and ~org-files-db-search~ calls fresh and uncached.
- Added package-controlled source-mutation staleness notifications for identifier creation and file rename operations.
