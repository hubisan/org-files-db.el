* Planning

** Problem summary

Large worker requests and results cross async.el as serialized Lisp, making transfer much slower than the cache build. An unsuccessful async child can bypass the finish callback, leaving the interactive waiter blocked until its 60-second timeout. Generation refresh, watch lifecycle, patch safety, and bounded fallback require end-to-end regression coverage.

** Goals

- Move large worker input and output through short-lived job-owned IPC files while keeping the async return envelope small.
- Guarantee cleanup and queue progress for success, rejection, cancellation, child death, and timeout.
- Keep warm lookup presentation-free and patch/search behavior generation-correct.
- Add quiet-by-default diagnostics and measurable worker/publication phases.
- Verify real file notification and interactive lifecycle behavior.

** Non-goals

- Persistent caches, Lisp threads, direct SQLite access, or TOML parsing.
- Caching direct ~org-files-db-query~ or ~org-files-db-search~ calls.
- Changes to Rust indexing behavior or dependencies.

** Architecture

- Keep lifecycle, queueing, transport, validation, waiting, watches, and diagnostics in ~org-files-db-cache.el~.
- Give each running job private request/result artifact paths. Patch base results use the request artifact; the child writes the complete replacement to the result artifact and returns only a bounded control envelope.
- Wrap async.el's sentinel and add a watchdog so every terminal state clears the active job and advances the queue.
- Validate generation, database ID, cache key, view token, refresh token, artifact metadata, and final status before atomic publication.

** Execution plan

1. Add diagnostics, timing state, IPC helpers, and job cleanup.
2. Refactor worker launch/result handling and terminal-process failure handling.
3. Make waiting callback-safe, generation-following, and bounded.
4. Exercise watch, poll, patch, search, source-dirty, and mode lifecycle paths.
5. Add worker transport and failure regressions plus benchmarks and documentation.
6. Run real-cache checks and ~make ci~.

** Risks & assumptions

- ~orgfdb status~ now returns a canonical absolute ~database_path~.
- IPC artifacts are transport-only and are removed on every handled lifecycle path.
- Original results and complete searchable candidate data remain available for actions and completion.
- A synchronous fresh query remains the final correctness fallback.

* Results

** Approach

- Traced enable, initial build, warm use, stale wait, notification, patch, callback, and follow-up-generation paths against the current code and async.el implementation.
- Reproduced the real 9,903-row cache.  The old worker did useful background preparation in about 2.65 seconds, but returning about 22 MB through async.el made publication take about 21.6 seconds.  A non-zero child exit skipped async.el's finish callback and left the active job installed until the 60-second interactive timeout.
- Moved large patch inputs and complete replacement payloads to short-lived job-owned files.  async.el now returns a small readable metadata/timing envelope.  The parent rejects obsolete metadata before reading the artifact, reconstructs process-local presentation state once, rechecks authoritative status, and publishes atomically.
- Wrapped the async sentinel and added a watchdog so child death, callback failure, timeout, rejection, cancellation, and mode shutdown all clear job state, remove artifacts, and advance the single-worker queue.
- Kept interactive waits bounded while servicing all processes and timers with ~accept-process-output~ on nil.  This lets callbacks, file notifications, watchdogs, and newer-generation jobs progress.
- Added quiet opt-in diagnostics for mode, status, watch, queue, worker, rejection, publication, warm lookup, and phase timings.
