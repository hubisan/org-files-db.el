Implement Step 5 of the ~org-files-db.el~ rebuild.

* Planning

** Problem summary

The rebuilt client has data access and completion candidates. It does not yet have one public structural query workflow.

** Goals

- Add the public ~org-files-db-query~ command.
- Keep ~org-files-db-query-results~ as the UI-free data interface.
- Use the shared presentation and completion pipeline.
- Select the default action from the query target.
- Let one call override the action.
- Pass the original Rust result to the action.
- Provide the effective configuration through dynamic action context.
- Return the selected original result to Lisp callers.
- Let an interactive prefix select another named configuration.

** Non-goals

- Do not port result navigation in this step.
- Do not port insert, rename, or link-target actions.
- Do not add watcher or cached-view code.
- Do not add Embark or Consult integration.
- Do not add presentation logic to Emacs.

** Architecture

~org-files-db-query-results~ remains the only one-shot data path.

~org-files-db-query~ resolves interaction choices around that data path. It then uses the common presentation reader.

The action receives only the selected original result. A dynamic configuration value is active only during the action call.

* Results

** Approach

~org-files-db-query~ now uses one query plus keyword arguments.

Interactive use reads one structural query. It uses the default configuration unless a prefix requests configuration selection.

The command calls ~org-files-db-query-results~, opens standard completion, and resolves the selected original result.

The command selects the default action from ~headings~, ~files~, or ~links~ when ~:action~ is absent.

~org-files-db-current-config~ exposes the effective configuration name only while the action runs.

The public query command returns the selected original result after the action finishes.
