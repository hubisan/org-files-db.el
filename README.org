This package is the Emacs client for [[https://github.com/hubisan/org-files-db][org-files-db]]. The ~orgfdb~ command line tool puts your Org files into a database (the index) and answers queries about their structure. With this package you run these queries from Emacs and select a result with the normal completion. Then you act on the result: you open it, insert a link to it, follow its link, or rename its file.

* Requirements

- Emacs 29.3 or newer
- The ~orgfdb~ executable, on your ~PATH~ or with an explicit path
- Optional: [[https://github.com/oantolin/embark][Embark]], for actions on results and for the export of the filtered results

* Quick start

Tell Emacs where ~orgfdb~ and your configuration file are. A configuration has a name and points to an ~orgfdb~ configuration file. If you do not select a configuration, Emacs uses the default configuration.

#+begin_src emacs-lisp
(require 'org-files-db)

(setq org-files-db-configs '(("main" . "~/org/org-files-db.toml")))
(setq org-files-db-default-config "main")
#+end_src

Run ~M-x org-files-db-check-setup~. It makes sure that the executable and the configuration file exist, shows the version, and makes sure that Emacs can read the database.

Run ~M-x org-files-db-query~ and type a query at the prompt, for example:

#+begin_example
(headings (not (done)))
#+end_example

This query lists all headings that are not done. Select one heading with your completion interface (the default interface, Vertico, Icomplete or Fido) and press ~RET~ to open it. This is the same query from Lisp:

#+begin_src emacs-lisp
(org-files-db-query '(headings (not (done))))
#+end_src

* Configuration

~org-files-db-executable~ is the command name or the path of ~orgfdb~. The default is ~"orgfdb"~.

~org-files-db-configs~ is an alist of named configurations. Each entry is ~(NAME . FILE)~. NAME is a unique name that is not empty. FILE is the path of an ~orgfdb~ configuration file. Use more than one entry if you keep separate indexes, for example one for work notes and one for private notes.

~org-files-db-default-config~ is the name of the entry that Emacs uses when you select none. You must set it when ~org-files-db-configs~ is not empty.

#+begin_src emacs-lisp
(setq org-files-db-configs
      '(("main" . "~/org/org-files-db.toml")
        ("work" . "~/work/org-files-db.toml")))
(setq org-files-db-default-config "main")
#+end_src

You can select a configuration for one call in three ways:

- Call ~org-files-db-query~ or ~org-files-db-check-setup~ with a prefix argument (~C-u~). Emacs then asks for a name from ~org-files-db-configs~.
- From Lisp, give ~:config "work"~ to ~org-files-db-query~.
- In a predefined view, set ~:config "work"~.

The configuration files must exist and Emacs must be able to read them. Emacs shows an error for an entry that is not valid, for two entries with the same name, and for a default configuration that does not exist.

* Queries

~M-x org-files-db-query~ reads a query as an Emacs Lisp form, runs it, and lets you select one result. The [[https://github.com/hubisan/org-files-db/blob/main/docs/reference/query-language.org][query language reference]] describes the query language. A query starts with a target, which is ~headings~, ~files~ or ~links~. Conditions follow the target.

#+begin_src emacs-lisp
(org-files-db-query '(headings (tags "public")))
(org-files-db-query '(links (status "resolved")))
(org-files-db-query '(files))
#+end_src

The query can be a quoted form or a string. When you call the command from Lisp, it returns the selected result. The command takes these keyword arguments:

- ~:config~: a name from ~org-files-db-configs~. The default is ~org-files-db-default-config~.
- ~:columns~: the columns to show
- ~:sort~: the sort order
- ~:row-source~: the row source, see [[*Row sources][Row sources]]
- ~:action~: a function that Emacs calls with the selected result instead of the default action

** Columns

~orgfdb~ formats the table of results. The [[https://github.com/hubisan/org-files-db/blob/main/docs/reference/presentation.org][presentation reference]] lists the column names that you can use. A column is a list with the column name and its options:

#+begin_src emacs-lisp
(org-files-db-query
 '(headings (not (done)))
 :columns '((todo-keyword :width (fixed 8))
            (outline-path :width (max 80))
            (file-name :width (max 30))))
#+end_src

- ~:width~ is ~auto~ (the width of the widest value), ~(max N)~ (automatic, but N characters at most) or ~(fixed N)~.
- ~:truncate~ is ~(:position left|middle|right :marker STRING)~. It sets how ~orgfdb~ shortens a value that is too long.
- ~:separator~, ~:include-root~ and ~:include-match~ change the outline path columns ~outline-path~, ~source-outline-path~ and ~target-outline-path~.
- ~:abbreviate-home t~ shows paths in your home directory as =~/...= in the columns ~file-dir~ and ~file-path~. ~file-dir~ is the directory of the file, so you can show it next to ~file-name~ without the file name twice. Actions still use the full path.

If you do not give ~:columns~, Emacs uses the default columns for the query target. You can change them with ~org-files-db-heading-columns~, ~org-files-db-file-columns~ and ~org-files-db-link-columns~.

** Sorting

~:sort~ is a list of columns. Each column can have ~:direction asc~ or ~:direction desc~. A sort column does not have to be a shown column.

#+begin_src emacs-lisp
(org-files-db-query
 '(headings (not (done)))
 :sort '((priority :direction asc)
         (outline-path :direction asc)))
#+end_src

If you do not give ~:sort~, Emacs uses ~org-files-db-heading-sort~, ~org-files-db-file-sort~ or ~org-files-db-link-sort~. All three are ~nil~ by default, and ~nil~ keeps the order that ~orgfdb~ returns. An explicit ~:sort nil~ keeps the ~orgfdb~ order, also when you set a default.

** Row sources

Usually each heading or file that matches is one row. A row source makes one row for each entry of a list in the match. Give it as ~:row-source~, as a symbol or a string. It works for heading queries and for file queries.

- ~tags~: one row for each tag. The heading ~* BJJ :sport:kampf:~ becomes two rows, one for ~sport~ and one for ~kampf~. The ~tag~ column shows the tag of each row.
- ~effective-properties~: one row for each property, also for inherited properties. The ~property-name~ and ~property-value~ columns show them.
- ~keywords~: one row for each file keyword, for example ~#+title~. The ~keyword-name~ and ~keyword-value~ columns show them.

A match with an empty list gives no row. For example, with ~:row-source tags~, headings without tags are not in the result. Each row points to its heading or file, so an action opens the same place for all rows of one match.

#+begin_src emacs-lisp
(org-files-db-query '(headings (todo))
                    :row-source 'tags
                    :columns '((tag :width (max 20))
                               (outline-path :width (max 80))))
#+end_src

** Faces

Emacs shows the cells with the faces of the ~org-files-db~ customization group, for example ~org-files-db-todo~, ~org-files-db-tag~ or ~org-files-db-file-name~. These faces inherit from the related Org faces.

* Predefined views

A view is a query with a name and its own columns, sort order and action. Define views in ~org-files-db-views~. Run a view with ~M-x org-files-db-view~, or from Lisp with ~(org-files-db-view "open-tasks")~.

#+begin_src emacs-lisp
(setq org-files-db-views
      '(("open-tasks"
         :query (headings (not (done)))
         :columns ((todo-keyword :width (fixed 8))
                   (outline-path :width (max 80)))
         :sort ((priority :direction asc)
                (outline-path :direction asc)))
        ("work-links"
         :config "work"
         :query (links (status "resolved"))
         :action org-files-db-actions-open-link-target)
        ("all-headings"
         :query (headings)
         :cache t)))
#+end_src

A view is a name and these keys. Each key can occur one time:

- ~:query~ (required): the query
- ~:config~: the configuration name. The default is ~org-files-db-default-config~.
- ~:columns~, ~:sort~, ~:row-source~: the same as for ~org-files-db-query~, with the same defaults
- ~:action~: the action for this view, see [[*Result actions][Result actions]]
- ~:cache~: ~t~ to use the cache, see [[*Cache][Cache]]
- ~:display~: ~buffer~ to show the view in a result buffer instead of in the minibuffer, see [[*Result buffer][Result buffer]]

Each view name must be unique. Emacs shows an error for a view that is not valid.

** Cache

~orgfdb~ prepares a view with ~:cache t~ in advance and keeps it current, so large results open faster. This works only while ~org-files-db-cache-mode~ is on. When the mode is off, each view runs as a normal query.

- ~M-x org-files-db-cache-start~ or ~(org-files-db-cache-mode 1)~ prepares all views with ~:cache t~. If watch mode is not on, cache mode also starts it.
- ~M-x org-files-db-cache-stop~ or ~(org-files-db-cache-mode -1)~ removes the prepared views. With a prefix argument, it also stops watch mode.

Cache mode reads the view definitions when it starts. If you change ~org-files-db-views~, ~org-files-db-configs~ or the default configuration, restart cache mode. The prepared views belong to the Emacs session that made them. Emacs removes them when you stop cache mode or exit Emacs.

** Candidate cache

While ~org-files-db-cache-mode~ is on, Emacs also keeps the completion candidates of each view with ~:cache t~, one entry for each view. When you open such a view again, it shows at once. So ~:cache t~ gives two things: the Emacs candidate cache and the view that ~orgfdb~ prepares.

Emacs does not keep the candidates of views without ~:cache t~, and keeps no candidates while the mode is off. Emacs uses the kept candidates again until the index, the view definition or the date changes. To find out whether the index changed, Emacs runs one short ~orgfdb status~ call. The cache has no size limit. When you turn ~org-files-db-cache-mode~ off or on, Emacs empties the cache. ~M-x org-files-db-cache-report~ shows the kept views in ~*org-files-db cache*~, with their rows, their approximate memory, the index generation and the build time.

** Watch mode

~orgfdb~ keeps the index current while a watcher process runs. ~org-files-db-watch-mode~ makes sure that a watcher runs for each configuration in ~org-files-db-configs~. If a watcher already runs outside Emacs, Emacs uses it and does not stop it. Emacs stops the watchers that it started when you stop the mode or exit Emacs.

- ~M-x org-files-db-watch-start~ or ~(org-files-db-watch-mode 1)~ starts the watchers.
- ~M-x org-files-db-watch-stop~ or ~(org-files-db-watch-mode -1)~ stops the watchers that Emacs started. This does not work while cache mode is on. Stop cache mode first.

~org-files-db-watch-startup-timeout~ is the number of seconds that Emacs waits until a watcher is ready. The default is 60. With ~nil~, Emacs waits without a limit.

* Full text search

~M-x org-files-db-search~ searches the titles and the body text of all headings and opens the place of the match, not only its heading. Each candidate is one match: the heading, the file and line, and the matched line with the match highlighted. With a prefix argument, you select the configuration first.

The input is a SQLite FTS5 expression: ~word~, ~pref*~ for a prefix, ~"two words"~ for a phrase, and ~AND~, ~OR~ and ~NOT~. FTS5 matches whole words, not parts of words. Use ripgrep for regular expressions or parts of words.

- With ~ivy-mode~, the candidates change while you type.
- With other completion UIs, you first type the expression and press ~RET~. Then you select a match.

The search starts only when the input has at least ~org-files-db-search-min-input~ characters (default ~3~). The face ~org-files-db-search-match~ marks the match.

Search needs ~fts5_enabled = true~ in the ~orgfdb~ configuration, and ~index_body_text = true~ to find body text. Run ~orgfdb rebuild~ after you change them. Search needs an ~orgfdb~ with ~search --occurrences~.

* Result actions

When you select a result, Emacs runs an action with it. The default action depends on the query target:

- ~org-files-db-heading-action~ for ~headings~
- ~org-files-db-file-action~ for ~files~
- ~org-files-db-link-action~ for ~links~

The default of all three is ~org-files-db-actions-open-result~. A view can set a different action with ~:action~. One call of ~org-files-db-query~ can also set it with ~:action~. An action is a function that takes the selected result as its only argument.

The package has these actions:

- ~org-files-db-actions-open-result~ opens a heading, a file, or the source of a link, at its position.
- ~org-files-db-actions-open-link-target~ opens the target of a link result. If ~orgfdb~ resolved the target (found it in the index), it opens the target heading or file. Org opens all other links, for example a web link, a directory or a file that is not in the index, as if you followed the link in its source file.
- ~org-files-db-actions-follow-heading-link~ opens the first link of a heading directly at its target. The target is a file, a heading, or Dired for a directory. The action looks in the headline first and then in the section. For a file result, it uses the first link before the first heading. Emacs does not show the buffer of the heading, and closes it again if it was not open before.
- ~org-files-db-actions-follow-or-open-heading~ follows a link in the headline itself, of any type. If the headline has no link, it opens the heading. Use it for headings that are links, for example an index or a path hierarchy of links to notes. With Embark, the key is ~j~. This view lists only headings with a link in the headline and follows that link. It needs a version of ~orgfdb~ with the ~source-context~ predicate:

  #+begin_src emacs-lisp
  (setq org-files-db-views
        '(("paths" :query (headings (has-link (links (source-context "heading"))))
                   :action org-files-db-actions-follow-or-open-heading)))
  #+end_src
- ~org-files-db-actions-insert-file-link~ inserts a ~file:~ link to a file result at point. If the current buffer visits a file, the link is relative to that file.
- ~org-files-db-actions-insert-heading-link~ inserts a link to a heading result at point:
  - If the heading has an ~ID~, it inserts an ~id:~ link.
  - If the heading has a ~CUSTOM_ID~, it inserts a file link to that ~CUSTOM_ID~.
  - If the heading has neither, ~org-files-db-create-heading-id~ decides. With ~nil~, the default, it inserts a file link with the heading title. With ~custom-id~, it adds a new ~CUSTOM_ID~ (made with ~org-id-new~) to the heading. With ~id~, it adds a new ~ID~. In both cases it saves the file and inserts a link to the new identifier.
  - For a file result, it inserts a file link.
- ~org-files-db-actions-rename-file~ renames the file of a result and changes the ~file:~ links to it in other files. If the text of a link is not the same as in the index, the action does not change that link and counts it in the message. The change edits more than one file and cannot be undone as one step, so use version control.

Some actions need more data than the list shows, for example the link actions and the rename action. These actions get the data from ~orgfdb~ when you run them. If ~orgfdb~ indexed the files again after Emacs made the list, the action stops with the message "Index changed, run the query again" and changes nothing. Then run the query again and select the result again.

* Renaming or moving a directory

~M-x org-files-db-rename-directory~ renames a directory or moves it to a different parent directory. It also changes the ~file:~ links in the index that point into the directory. The command asks for the directory and for the new path. A name without a path keeps the directory in the same parent. If the parent of the new path does not exist, the command creates it. With a prefix argument, the command also asks for the configuration.

- In Dired, the default directory is the directory at point. On a file line, it is the directory that Dired shows. After the change, Emacs updates the Dired buffer that shows the parent.
- With Embark, ~M~ in the file action map (~embark-file-map~) runs ~org-files-db-embark-rename-directory~ on the directory at point or in the minibuffer. It asks only for the new path. If ~M~ already has a binding, Emacs keeps that binding.
- The command changes links from files outside the directory to files inside it. These links keep their format, description, search option, and relative or absolute form. It also changes links to the directory itself.
- Relative links between files inside the directory stay the same, unless they go through the directory name, for example ~../dir/file.org~. The command changes absolute links between files inside the directory.
- When you move the directory to a different parent, the command also changes relative ~file:~ links from files inside the directory to files outside it. The links stay relative to the new location. Absolute links stay the same. A rename in the same parent does not change relative links.
- The command gets the links from ~orgfdb~ and checks the state of the index. If the index changed, the command stops with "Index changed, run the query again" before it changes anything.
- The command shows its plan in ~*org-files-db rename directory*~, similar to a diff. For each file, the plan shows each link with its line number, the old text as a removed line and the new text as an added line. After the changes, the plan lists the links that the command skips. Nothing changes until you confirm. If the text of a link is not the same as in the index, the command skips that link and counts it in the message.
- The command stops if the new path exists or is inside the directory. It also stops if a buffer that visits an affected file, or a file inside the directory, has unsaved changes. Buffers that visit files inside the directory move with the directory.
- If a step fails, the command restores the edited files and moves the directory back. The error message lists each change that the command did not undo.
- The command does not check whether the directory is the root of a directory in your configuration. Do not move such a root.

~M-x org-files-db-undo-rename-directory~ undoes the last rename or move of the Emacs session. It restores the original text of the edited files and moves the directory back. It first shows the files whose links it restores and asks for confirmation. It changes nothing in these cases: the new directory does not exist, the old path exists again, an edited file changed after the rename, or a buffer that visits an edited file has unsaved changes. The undo does not call ~orgfdb~. After a successful undo, Emacs forgets the rename.

* Result buffer

You can show all rows in a read-only buffer instead of selecting one result in the minibuffer.

- ~M-x org-files-db-show-view~ asks for a view and shows it in ~*org-files-db: NAME*~.
- ~M-x org-files-db-show-query~ reads a query like ~org-files-db-query~ and shows it in ~*org-files-db: query*~.
- ~(org-files-db-show-query QUERY &rest KEYS)~ takes the same keywords as ~org-files-db-query~: ~:config~, ~:columns~, ~:sort~, ~:row-source~ and ~:action~. ~(org-files-db-show-view NAME)~ does the same for a view. Both functions return the buffer.
- ~org-files-db-view~ also shows a view with ~:display buffer~ in this buffer. The only valid values of ~:display~ are ~buffer~ and ~nil~.

#+begin_src emacs-lisp
(setq org-files-db-views
      '(("Next" :query (headings (todo "NEXT")) :display buffer)))

(org-files-db-show-query '(headings (todo "NEXT")))
#+end_src

The buffer uses ~org-files-db-export-mode~ and does not need Embark. Each line is one row, as the table shows it. These keys work in the buffer:

- ~RET~ runs the action of the view or of the call. Without one, it runs the default action for the kind of result.
- ~o~ exports the rows as an outline, see [[*Outline export][Outline export]].
- ~g~ runs the query again and keeps point on the same line number.
- ~n~ and ~p~ go to the next line and to the previous line.

If the query finds nothing, the buffer shows one line, "No results". When you show the same view or query again, Emacs uses the same buffer. Emacs does not update the buffer automatically.

* Embark integration

You do not need Embark. Results use the completion category ~org-files-db-result~. When Embark is loaded, ~embark-act~ on a result offers the actions of ~org-files-db-embark-result-map~:

- ~o~ opens the result
- ~t~ opens the link target
- ~f~ inserts a file link
- ~h~ inserts a heading link
- ~l~ follows the first link in the heading
- ~j~ follows the link in the headline, or opens the heading
- ~r~ renames the file

~embark-export~ lists the rows that match the current filter in the minibuffer, in the order that you see. It shows them in an ~*org-files-db export*~ buffer that uses ~org-files-db-export-mode~. These keys work in that buffer:

- ~RET~ runs the default action for the result on the current line.
- ~n~ and ~p~ go to the next line and to the previous line.
- ~embark-act~ on a line offers the same actions as in the minibuffer.
- ~o~ exports the rows as an outline, see below.

** Outline export

~org-files-db-embark-export-outline~ exports heading results as an Org outline of links. It shows the outline in the read-only buffer ~*org-files-db outline*~. First run ~embark-export~ (~E~) on the results. Then press ~o~ in the ~*org-files-db export*~ buffer to make the outline from its rows. For all other kinds of results, the export stops with "Outline export needs heading results". ~org-files-db-outline-export~ does the same from Lisp, for a list of heading records and their presentation.

Each file becomes a top-level heading with a link to the file. Its headings are one level deeper than in the file. Each headline keeps its TODO keyword, its priority and its own tags, but not inherited tags. The title is a link to the heading:

- ~file:PATH::#CUSTOM_ID~ if the heading has a ~CUSTOM_ID~
- else ~id:ID~ if the heading has an ~ID~
- else ~file:PATH::LINE~

The face ~org-files-db-outline-match~ marks the headings that match the query. ~C-x C-s~ in the buffer saves the text to a file, without faces.

The structure comes from ~orgfdb~, and the text comes from the source files. If the index is not the same as a file, the export stops with "Index changed, run the query again" and exports nothing.

- ~org-files-db-outline-export-ancestors~ (default ~t~) keeps the ancestors of the headings that match. With ~nil~, the outline lists only the headings that match, all on level 2 under their file.
- ~org-files-db-outline-export-children~ (default ~nil~) adds links to child headings of the headings that match. With ~children~, it adds the direct children. With ~subtree~, it adds all descendants.
- ~org-files-db-outline-export-planning~ (default ~t~) copies the planning line.
- ~org-files-db-outline-export-properties~ (default ~nil~) copies the property drawer of the headings that match.
- ~org-files-db-outline-export-body~ (default ~nil~) copies the body text of the headings that match.

Ancestors and added children get only their headline. Ancestors also get their planning line. They never get properties or body text.

* Development

#+begin_src shell
make setup
make ci
#+end_src

- ~make setup~ installs the development dependencies with [[https://emacs-eask.github.io/][Eask]].
- ~make ci~ runs all checks: package, install, byte-compilation, linters and Buttercup tests.
- ~make check-offline~ runs the same checks without Eask, with packages from GitHub. Use it where Eask cannot get packages from the package archives.
- ~make test~ runs only the Buttercup tests.
- ~make fmt~ formats the Emacs Lisp files.
- ~make bench~ runs the benchmark against a real ~orgfdb~. [[file:docs/benchmark.org][docs/benchmark.org]] has the results.
